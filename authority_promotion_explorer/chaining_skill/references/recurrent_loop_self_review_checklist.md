# Recurrent Loop Self-Review Checklist: Two-Phase Board-v2

Use this after materializing the first draft. It is advisory quality review, not a static rejection gate. Keep the fixed five-role topology. Make a field-level revision only when route ids/order/boundaries remain sound; otherwise replace the whole task-route list while preserving the five skill names, role order, board path, and renderer-owned control flow.

1. Entry frontmatter says it is the broad startup and mandatory return selector for the entire requested task, not merely a first-item helper. It makes board creation/read and return-ticket consumption necessary before broad discovery, source edits, global verification, task continuation, or a response.
2. Each generator-private card is one real vertically complete bounded unit: one runtime-manifest pre-mutation probe, one task-visible anchor, one direct task-native mutation, one private complete scoped_check command, and one short command-free check_intent. Render only check_intent; never copy a raw shell/Python command into entry, a packet, lease, or board. Its mutation and check must not require a helper, global run, later output, or future acceptance result. In a dependency chain, an earlier configuration/parameter card must stop at its own anchor; a later simulation, log, calculation, or metric is a separate card. Never merge deliverables, use a missing output as an initial probe, duplicate a forward anchor, or authorize a multi-output driver. A separately named final output has its own card. Each card has an internal-only work_unit with one fixed kind (source_to_file, source_to_json, artifact_to_trace, or trace_to_json), only current runtime-manifest inputs or earlier anchors, output_path agreeing with work_anchor, a matching local validation_mode, next pass_target, and same-card rework_target. source_to_json never runs a simulator; artifact_to_trace alone may run it; trace_to_json writes only its report. It is a generator/self-review aid only: never render those keys into a SKILL, packet, lease, or board.
3. Render entry with only compact selector clauses `id -> probe -> anchor -> check_intent`: bootstrap may name the first id and a return may name only its ticket id. Never render a raw verifier command, shell/Python code, future long check, or full card table. Create mutation and the selected check_intent only in the dynamically selected packet after the probe. Non-entry roles see only packet/lease/outcome, never catalog, future anchor, or lookup.
4. Bootstrap explicitly sets `stage_epoch=0`, `record_generation=0`, `handoff_complete=false`, `summary_permitted=false`, and `response_permitted=false`, in addition to every runtime key. Return rework reads `return_checkpoint.verifier_status.status`, not a cleared top-level field.
5. Entry, continuation, and verifier use a two-phase transition after one role action: a board-only result commit keeps the current active role with `handoff_to=null`; the exact next physical action is the board-only successor handoff. Nothing non-board may occur between them. Binder’s fresh board read locks one atomic local consume-and-bind-and-activate patch; it may not leave a consume-only or lease-only state.
6. Gate’s first and only patch after its board read atomically consumes verifier handoff, writes the actual passed/rework checkpoint, revokes lease, clears packet, activates entry, and stores the entry marker. Gate never selects next work.
7. The literal marker is followed by successor SKILL read, board read, and stub consumption before task work, a message, plan, summary, or reply.
8. Every skill's first action is its standalone board read; ban `rg --files`, `rg`, `ls`, globs, repository discovery, and task-wide planning before that read. Continuation may create/revise only the lease anchor, never a helper, driver, script, executable, workflow, auxiliary output, or second anchor; immediately make its result commit and successor handoff. Do not propose batch commands, terminal branches, whole-task closeout, broad global checks, or stricter static wording gates. Green evidence is routing input, not closeout authority.

For a revision, change only the entry task anchor and existing route-card fields. Preserve names, board path, role order, and catalog ids. A malformed/unavailable review is a warning: retain the validated first draft.
